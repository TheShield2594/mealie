# iOS App

The iOS app wraps the regular frontend with [Capacitor](https://capacitorjs.com/). It bundles a static
build of `frontend/` and talks to a Mealie server that the user enters on first launch. There is no
separate codebase: a change to the frontend shows up in the app at its next build.

You don't need a Mac. The app is compiled on GitHub's macOS runners (`.github/workflows/ios.yml`).

## How it differs from the web app

| | Web | iOS app |
|---|---|---|
| Where the page comes from | The Mealie server | Bundled in the app, served from `capacitor://localhost` |
| API URLs | Relative (`/api/...`) | Prefixed with the chosen server (`serverUrl()` in `app/lib/native/server.ts`) |
| Session | `mealie.access_token` cookie, set by the server | Token kept in the iOS app's own storage, sent as a `Bearer` header |
| Service worker / web manifest | Yes | No (`MEALIE_NATIVE=true` turns them off) |

On first launch, `app/plugins/00.native-app.client.ts` asks for the server address and checks that
`/api/app/about` answers. The login page shows the server and a **Change server** link.

The server allows the `capacitor://localhost` origin through CORS (`mealie/app.py`) without
credentials, so **the server has to run this version of Mealie** for the app to connect.

When you add a URL that the browser loads directly (an `<img src>`, `fetch`, `window.open`), wrap a
server-relative path in `serverUrl()`. API client routes and `$axios` calls are already covered.

## Building

```bash
cd frontend
pnpm generate:ios        # static build with MEALIE_NATIVE=true, then `cap sync ios`
```

This writes the bundle into `frontend/ios/App/App/public` (git-ignored). Compiling the Xcode project
needs macOS. In CI, the **iOS App Build** workflow runs this command and then builds the project for the
simulator without signing it. You can start it by hand from the Actions tab.

## Project layout

- `frontend/capacitor.config.ts`: app ID, name, and plugin settings
- `frontend/ios/App/`: the Xcode project, generated by `npx cap add ios`. Committed, and edited for the
  icon, `Info.plist` and signing.
- `frontend/ios/App/App/Assets.xcassets/AppIcon.appiconset/AppIcon-512@2x.png`: the app icon. It has
  to be 1024×1024 PNG with no transparency.

## Not supported in the app yet

- OIDC login (the button is hidden). The web redirect lands in Safari, not the app.
- File downloads (backups, recipe PDF and ZIP exports). They rely on the session cookie and on browser
  downloads, and WKWebView supports neither.
- Plain `http://` servers outside the local network. App Transport Security allows `http://` only for
  local network addresses, so a remote server needs HTTPS.

## Releasing to TestFlight

You need these accounts and keys first:

1. An [Apple Developer Program](https://developer.apple.com/programs/) membership.
2. An App ID registered for the bundle ID in `capacitor.config.ts`.
3. An app record in App Store Connect.
4. An App Store Connect API key with the App Manager role, stored as GitHub Actions secrets.

The signing and upload job is not written yet.
